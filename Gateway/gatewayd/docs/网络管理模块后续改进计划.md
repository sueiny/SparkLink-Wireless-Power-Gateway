# 网络管理模块后续改进计划

本文记录 `gatewayd` 网络管理模块在 P0 稳定性修复后的后续工作。当前结论是：网络模块先暂停继续改动，保持已验证的 Wi-Fi + MQTT + SLE 上云基线，不再追加 P1/P2 结构改造，除非重新开启专项。

## 1. 当前状态

当前现场主网络配置为：

- `network.mode=wifi`
- `wifi.ifname=wlan0`
- MQTT host 为 `thingskit.aiotcomm.com.cn:11883`
- MQTT 连接实际依赖系统默认路由和全局 DNS，`expected_ifname=wlan0` 只表示期望接口，不表示 socket 已强制绑定。

已落地并验证的 P0 内容：

- `WifiProvider::bringUp()` 已先检查目标 SSID + 有效 IPv4，满足时复用当前 Wi-Fi，不再重启 DHCP/Wi-Fi。
- 已移除全局 `killall udhcpc`、`killall wpa_supplicant` 路径，避免误伤其它接口。
- DHCP 已优先复用正在运行的 `dhcpcd` 针对目标接口续租，未检测到 `dhcpcd` 时才使用 `udhcpc`。
- Wi-Fi provider 不再直接删除 eth0/eth2 默认路由，默认路由统一由 `NetManager`/`netlink_utils` 修正。
- `NetManager` 对当前接口 link/IP 短暂失败增加连续失败容忍。
- 云端 TCP 探测失败时输出 DNS、路由、TCP 原因。
- `netlinkSetDefaultRouteVia()` 对目标默认路由已存在的情况做幂等成功处理。
- MQTT 连接日志改为 `expected_ifname=...`，避免误解为真实接口绑定。

已观察到的板端基线：

- 默认路由为 `default via 192.168.50.1 dev wlan0 metric 100`。
- 网关状态持续上报 `network_type=wifi`、`network_ifname=wlan0`、`cloud_connected=1`。
- 真实 SLE 上行压测中，42 设备批次可持续发布到 `v1/gateway/telemetry`。
- `telemetry_cache` 保持为 0。
- `/etc/resolv.conf` 仍可能由 `eth2.dhcp` 生成，Wi-Fi DNS 作为后续 nameserver 存在；这是后续 DNS 治理问题，不是 P0 阻塞项。

2026-06-16 补充回归：

- `gatewayd` 启动后仅出现一次 `wifi bringUp ok`，随后持续 `keep selected wifi wlan0, cloud=reachable`。
- METER_001 三路 COM 基线和 `topology-all` 60 秒压测期间没有重复 Wi-Fi flush、DHCP 重启或 provider 重选。
- `topology-all` 每口发送 11 轮、462 帧，覆盖 31 个 DTU 节点和 11 个外设。
- MQTT 持续发布 64/62/126 设备批次，`telemetry_cache=0`。
- 当前 `/etc/resolv.conf` 仍显示 `eth2.dhcp` 在前、`wlan0.dhcp` 在后：`nameserver 192.168.0.1`、`nameserver 192.168.50.1`。本轮只验证默认路由和 MQTT 稳定，不继续修改 DNS 策略。

## 2. 暂停边界

暂停期间不继续做以下改动：

- 不拆 `NetworkState` 字段。
- 不引入新的网络状态机。
- 不改 MQTT topic、payload、连接凭证或 ThingsKit 协议。
- 不实现 MQTT socket 真实接口绑定。
- 不改 `dhcpcd` hook、`resolv.conf` 写入策略或系统 DNS 管理。
- 不实现 cellular 拨号、PPP、ECM/NCM。
- 不重命名 `netlink_utils` 或大规模重构路由工具层。

允许的维护范围：

- 文档补充和测试记录归档。
- 明确 bug 的小修，例如编译失败、日志字段拼写错误、明显空指针或越界。
- 板端回归脚本和排障命令补充，但不改变网络策略。

## 3. 后续 P1 计划

P1 目标是增强可维护性和排障能力，不改变现有上云路径。

建议拆成独立小步：

1. 增加内部 `NetworkCheckResult`
   - 将当前 `available/cloud_reachable` 之外的失败原因拆成 `link/ip/route/dns/tcp`。
   - 先作为 `NetManager` 内部结构使用，不急于改外部接口。
   - 验收：日志能明确区分 `link_not_ready`、`ip_not_ready`、`dns_not_ready`、`tcp_timeout`。

2. 增加重拉起退避
   - 当前已对短暂失败做连续失败容忍，但真正进入 `bringUp()` 后仍可能连续重试。
   - 增加上次重拉起时间和退避窗口，避免长期异常时反复重置 `wlan0`。
   - 验收：连续异常时日志显示退避原因，不频繁执行 `wpa_cli terminate`。

3. 拆分网络诊断辅助
   - 将 DNS、route、TCP 探测摘要整理为小函数，避免 `network_utils.cpp` 继续膨胀。
   - 保持函数命名为 `camelCase`，不引入新框架。
   - 验收：`build-gw` 通过，日志字段保持兼容。

4. 补充最小可复现测试入口
   - 增加只检查网络状态的板端命令集合或 driver 子命令。
   - 输出 route、wlan0 IPv4、resolv.conf、MQTT 状态、cache 数量。
   - 验收：一次命令能收集 Wi-Fi/MQTT 失败排查所需的最小证据。

## 4. 后续 P2 计划

P2 属于结构优化或平台策略改动，必须单独开专项，不能混入普通联调。

候选项：

- DNS 治理
  - 研究 `dhcpcd` hook、`resolv.conf.head/tail` 或网关自维护 DNS 优先级策略。
  - 目标是避免 eth2 DHCP nameserver 长期排在 wlan0 前面。
  - 风险是影响系统其它服务 DNS 行为。

- MQTT 真实接口绑定
  - 评估当前 sysroot/libmosquitto 是否支持稳定的源地址或接口绑定。
  - 如果走 `SO_BINDTODEVICE`，必须验证当前 RK3506 内核、权限和 mosquitto 回调行为。
  - 如果不能稳定绑定，继续保持默认路由策略，并在文档里明确边界。

- 路由工具层收敛
  - 当前 `netlink_utils` 读取 `/proc/net/route`、添加路由用 Netlink、删除部分路由使用 `ip route del`。
  - 后续可整理为 `route_manager` 风格命名，但不应在功能联调期做。

- Cellular 兜底链路
  - 实现 AT/PPP 或 ECM/NCM 前，需要先确认硬件模块、串口、APN、拨号方式。
  - 未确认之前不把 cellular 当作真实兜底能力承诺。

## 5. 重新开启条件

满足以下任一条件时，再考虑恢复网络模块改进：

- Wi-Fi/MQTT 在真实上云测试中出现可复现断连，且日志指向网络模块策略。
- 需要正式支持以太网/Wi-Fi/cellular 自动切换。
- 平台验收要求明确证明 MQTT 走指定物理接口。
- DNS 被 eth2/其它接口抢占导致 ThingsKit 解析失败并可复现。

恢复前必须先固定基线：

```bash
bash .claude/skills/run-gateway/driver.sh build-gw
bash .claude/skills/run-gateway/driver.sh push
bash .claude/skills/run-gateway/driver.sh test-real-listen
adb shell "ip route"
adb shell "ip -4 addr show wlan0"
adb shell "cat /etc/resolv.conf"
adb shell "grep -E 'NET|MQTT|expected_ifname|transient failure|cannot reach cloud|cloud_connected' /userdata/gateway/data/log/gateway.log | tail -200"
adb shell "/userdata/gateway/bin/sqlite3 /userdata/gateway/data/gateway.db 'SELECT COUNT(*) FROM telemetry_cache;'"
```

## 6. 当前建议

网络模块先保持暂停。下一阶段优先继续真实 DTU/SLE 数据链路、命令下发真实执行、串口并发测试和物模型一致性验证。网络模块只作为支撑能力观察，不再主动重构。
