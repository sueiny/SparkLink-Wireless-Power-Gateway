> Status: Current board-test workflow.

本文记录 RK3506 Gateway 当前板端实测的标准操作流程，适用于验证 `gatewayd`、`sle_data_app`、网络管理、MQTT 上云、ST `DATA/05/06` 上报和两路 DTU root 联调。

## 1. 测试目标

板端实测至少要确认以下链路：

| 链路 | 验收点 |
| --- | --- |
| 网络管理 | `gatewayd` 能按配置选中网络接口，默认路由不漂移，MQTT 可达。 |
| MQTT 上云 | `cloud_connected=1`，telemetry/status 能成功 publish。 |
| SLE IPC | `gatewayd` 监听 SLE data/cmd 抽象 socket，`sle_data_app` 能连接。 |
| Root 上报 | `0x05` 拓扑、`0x06` 外设映射、`DATA` 遥测能被解析。 |
| 动态拓扑 | DTU/外设在线状态只由最新有效快照决定。 |
| 缓存补传 | 云不可达时进 SQLite 缓存，恢复后能补传。 |

## 4. 基础启动流程

### 4.1 停止旧进程并清理日志

```bash
adb shell "killall -9 gatewayd 2>/dev/null; killall -9 sle_data_app 2>/dev/null; sleep 1"
adb shell "rm -f /tmp/gatewayd.log /tmp/sle_data_app.out /userdata/gateway/data/log/gateway.log"
adb shell "mkdir -p /var/run/gateway /userdata/gateway/data/log"
```

### 4.2 启动 gatewayd

```bash
adb shell "nohup /userdata/gateway/bin/gatewayd --config /userdata/gateway/config/gateway_config.json >/tmp/gatewayd.log 2>&1 &"
```

确认进程和日志：

```bash
adb shell "ps | grep gatewayd | grep -v grep"
adb shell "tail -80 /tmp/gatewayd.log 2>/dev/null; tail -80 /userdata/gateway/data/log/gateway.log 2>/dev/null"
```

### 4.3 确认 SLE IPC socket

```bash
adb shell "cat /proc/net/unix | grep -E '@var/run/gateway/sle_data.sock|@/var/run/gateway/sle_data.sock'"
adb shell "cat /proc/net/unix | grep -E '@var/run/gateway/sle_cmd.sock|@/var/run/gateway/sle_cmd.sock'"
```

预期：

- data socket 已监听。
- cmd socket 在命令通道初始化后可见。

## 5. 网络管理实测

### 5.1 当前配置确认

查看板端实际配置：

```bash
adb shell "sed -n '17,41p' /userdata/gateway/config/gateway_config.json"
```

当前代码约定：

| 接口类型 | 优先级 | 默认 route metric |
| --- | --- | --- |
| Ethernet | 最高 | `100` |
| Wi-Fi | 第二 | `200` |
| Cellular/4G | 最低 | `300` |

注意：

- `network.mode=ethernet|wifi|cellular` 是固定模式，不跨 provider 抢占；但默认路由、DNS、MQTT 仍要对齐到该接口。
- `network.mode=auto` 是抢占式优先级，按 `ethernet -> wifi -> cellular` 选择；更高优先级链路恢复后，会在下一检查周期内抢占。
- 当前 `cellular` provider 不负责拨号，只能接管已经存在且有 IP 的 `ppp0/usb0/wwan0`。

### 5.2 Wi-Fi 单路径实测

适用于 `network.mode=wifi`：

```bash
adb shell "ip addr show wlan0"
adb shell "ip route show default"
adb shell "grep '^nameserver' /etc/resolv.conf"
adb shell "grep -E 'selected wifi|keep selected wifi|dns realigned|network interface changed|cloud_connected|publish success' /userdata/gateway/data/log/gateway.log | tail -120"
```

通过条件：

- `wlan0` 有非 `169.254/16` IPv4。
- 默认路由走 `wlan0`，metric 为 `200`。
- `/etc/resolv.conf` 只保留 `wlan0` 对应 DNS，不混入其它接口 nameserver。
- 即使 `eth1` 恢复可上云，也不得切换到 `eth1`。
- 日志出现 `selected wifi wlan0` 或 `keep selected wifi wlan0`。
- 日志出现 `cloud_connected":1` 或 MQTT publish success。

### 5.3 Auto 优先级实测

测试 `auto` 前，将配置改为：

```json
"network": {
  "mode": "auto",
  "priority": ["ethernet", "wifi", "cellular"]
}
```

推送配置后重启：

```bash
adb push app/Gateway/gatewayd/config/gateway_config.json /userdata/gateway/config/
adb shell "killall -9 gatewayd 2>/dev/null; nohup /userdata/gateway/bin/gatewayd --config /userdata/gateway/config/gateway_config.json >/tmp/gatewayd.log 2>&1 &"
```

按顺序做三段：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 起始 Wi-Fi | 保证仅 `wlan0` 可上云 | 选中 Wi-Fi，默认路由 metric `200`，`/etc/resolv.conf` 只含 Wi-Fi DNS。 |
| 以太网恢复 | 接上 `eth1` 并保证 DHCP/外网可用 | 下一检查周期内抢占到 ethernet，默认路由切到 `eth1 metric 100`，DNS 改成 `eth1`，MQTT 断开并重连。 |
| 以太网断开 | 拔掉 `eth1` 或让其不可上云 | 自动回退到 `wlan0`，默认路由/DNS/MQTT 全部跟随回退。 |

检查命令：

```bash
adb shell "ip route show default"
adb shell "grep '^nameserver' /etc/resolv.conf"
adb shell "grep -E 'selected|keep selected|preempt selected|higher priority|network interface changed|dns realigned|cannot reach cloud' /userdata/gateway/data/log/gateway.log | tail -160"
```

通过条件：

- `wlan0 -> eth1` 抢占时，日志出现 `preempt selected ethernet eth1 from wifi wlan0`。
- MQTT 随接口变化出现 `network interface changed wlan0 -> eth1`，随后恢复 `cloud_connected=1`。
- 回退到 `wlan0` 后，默认路由和 `/etc/resolv.conf` 都回到 Wi-Fi。

### 5.4 路由/DNS 漂移实测

只在实验环境执行。先记录当前路由：

```bash
adb shell "ip route show default"
adb shell "cat /etc/resolv.conf"
```

制造漂移示例：

```bash
adb shell "ip route add default via <gateway_ip> dev <other_ifname> metric 50"
```

观察：

```bash
adb shell "sleep 8; ip route show default"
adb shell "grep -E 'ROUTE_DRIFT|route via|keep selected|selected|dns mismatch|dns realigned' /userdata/gateway/data/log/gateway.log | tail -160"
```

通过条件：

- `gatewayd` 检测到当前选中接口默认路由异常。
- 能修复时，默认路由回到当前选中接口和对应 metric。
- 当前接口对应 DNS 被其它接口覆盖时，下一检查周期内会自动重写 `/etc/resolv.conf`。
- 不能修复时，日志出现 `ROUTE_DRIFT`，不会继续静默宣称错误接口可用。

制造 DNS 漂移示例：

```bash
adb shell "printf 'nameserver 1.1.1.1\n' >/etc/resolv.conf"
adb shell "sleep 8; cat /etc/resolv.conf"
```

恢复命令：

```bash
adb shell "ip route del default dev <other_ifname> 2>/dev/null || true"
adb shell "killall -9 gatewayd 2>/dev/null; nohup /userdata/gateway/bin/gatewayd --config /userdata/gateway/config/gateway_config.json >/tmp/gatewayd.log 2>&1 &"
```

### 5.5 DHCP renew 实测

当前业务接口场景：

```bash
adb shell "dhcpcd -n <selected_ifname> 2>/dev/null || udhcpc -i <selected_ifname> -n -q"
adb shell "sleep 5; ip route show default"
adb shell "grep '^nameserver' /etc/resolv.conf"
adb shell "grep -E 'route via|keep selected|selected|dns realigned|cloud_connected|publish success' /userdata/gateway/data/log/gateway.log | tail -160"
```

通过条件：

- 对当前接口 renew 后，默认路由仍落在当前接口。
- `/etc/resolv.conf` 仍只保留当前接口 DNS。
- MQTT 能继续连接或自动恢复。

非当前接口 renew：

```bash
adb shell "dhcpcd -n <non_selected_ifname> 2>/dev/null || true"
adb shell "sleep 5; ip route show default"
adb shell "grep '^nameserver' /etc/resolv.conf"
```

通过条件：

- 非当前接口 renew 不得抢走默认路由。
- 非当前接口 renew 不得把 `/etc/resolv.conf` 留成自己的 nameserver。

## 6. MQTT 上云实测

### 6.1 快速检查

```bash
adb shell "grep -E 'cloud_connected|publish success|MQTT|cannot reach cloud' /userdata/gateway/data/log/gateway.log | tail -120"
```

通过条件：

- 网关状态上报含 `cloud_connected:1`。
- telemetry 或 gateway status 出现 `publish success`。
- 如果云不可达，SQLite 缓存增加，恢复后缓存下降。

### 6.2 缓存检查

```bash
adb shell "/userdata/gateway/bin/sqlite3 /userdata/gateway/data/gateway.db 'SELECT COUNT(*) FROM telemetry_cache;'"
```

判断：

- 在线稳定时应接近 `0`。
- 断网压测时会上升。
- 网络恢复后应逐步下降。

### 7.3 观察日志

```bash
adb shell "grep -E 'ST 0x05 accepted|ST 0x06 accepted|SLE-IPC|SLE-TOPO|telemetry batch|publish success|modbus_parse_error|CRC|invalid frame' /userdata/gateway/data/log/gateway.log | tail -200"
```

通过条件：

- `ST 0x05 accepted root=101` 和 `root=10`。
- `ST 0x06 accepted root=101`；root=10 为纯 DTU 树，可上报空 0x06。
- `observed_dtu` 不超过 `expected_dtu_count`。
- `observed_external` 不超过 `expected_external_device_count`。
- 未知 DTU/外设会拒绝该帧，不污染旧快照。
- `DATA` 解析后进入 telemetry publish。
- 无持续 `CRC error`、`invalid frame`、`modbus_parse_error`。

## 9. 常见问题定位

| 问题 | 优先检查 |
| --- | --- |
| MQTT 不可达 | `ip route show default`、`/etc/resolv.conf`、`cannot reach cloud` 日志。 |
| 显示选中 Wi-Fi 但实际走以太网 | 查 `ROUTE_DRIFT`、默认路由 metric、`route via wlan0 metric=200` 日志。 |
| Wi-Fi 连不上 | 查 `WIFI-*` 错误码、`wpa_cli -i wlan0 status`、`iw dev wlan0 link`。 |
| root 拓扑不上报 | 查 `ST 0x05 parse failed`、root payload 根节点是否等于 ST header `src_node_id`。 |
| 外设不在线 | 查 `ST 0x06 accepted`、设备是否在 JSON inventory、映射 DTU 是否在 05 快照中在线。 |
| 下行失败 | 查设备是否在 06 映射中在线、能否从动态拓扑找到 root。 |
| 缓存不下降 | 查 MQTT 是否 connected、`telemetry_cache` 数量、publish success 日志。 |
