# 数据包格式大全

日期：2026-06-17  
范围：`app/Gateway` 全部协议层数据包格式，包括 SLE 树网络帧、IPC 命令协议、MQTT Topic 与 JSON Payload。

## 数据流总览

```text
SLE Devices ←→ SLE Radio ←→ sle_data_app ←→ [Unix Socket IPC] ←→ gatewayd ←→ [MQTT] ←→ Cloud (ThingsKit)
```

上行链路：设备 → SLE 无线 → sle_data_app → IPC 数据通道 → gatewayd → MQTT 上云  
下行链路：云端 MQTT → gatewayd → IPC 命令通道 → sle_data_app → SLE 无线 → 设备

## 一、SLE 树网络帧格式 (ST Frame)

**定义文件**：`gatewayd/include/codec/sle_frame_parser.h`  
**解析实现**：`gatewayd/src/codec/sle_frame_parser.cpp`

### 1.1 帧头 (13 字节)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | magic_0 | 0x53 ('S') |
| [1] | 1B | magic_1 | 0x54 ('T') |
| [2] | 1B | version | 0x01 |
| [3] | 1B | frame_type | 帧类型 (见 1.2) |
| [4] | 1B | src_role | 角色 (见 1.3) |
| [5-6] | 2B | src_node_id | 源节点 ID (小端) |
| [7-8] | 2B | dst_node_id | 目标节点 ID (小端) |
| [9-10] | 2B | seq | 序列号 (小端) |
| [11-12] | 2B | payload_len | 载荷长度 (小端) |
| [13-N] | NB | payload | 可变载荷 |

帧最大长度：256 字节  
最大载荷：243 字节 (256 - 13)

### 1.2 帧类型

| 值 | 名称 | 说明 |
|----|------|------|
| 1 | HEARTBEAT | 心跳/存活检测 |
| 2 | DATA | 传感器数据或控制数据 |
| 3 | TOPO_SUMMARY | 拓扑通告 |
| 4 | DEPTH_UPDATE | 树深度更新 |

### 1.3 角色

| 值 | 名称 | 说明 |
|----|------|------|
| 1 | ROOT | 根节点 |
| 2 | RELAY | 中继节点 |
| 3 | LEAF | 叶子节点 |
| 4 | GATEWAY | 网关 |

### 1.4 固定节点 ID

| 值 | 名称 |
|----|------|
| 0x0000 | GATEWAY |
| 0x0001 | ROOT_1 |
| 0x0002 | ROOT_2 |
| 0x0003 | ROOT_3 |

### 1.5 结构体定义

```c
// SLE 帧头解析结果（13 字节帧头）
struct SleFrameHeader {
    uint8_t  frame_type;
    uint8_t  src_role;
    uint16_t src_node_id;    // 小端
    uint16_t dst_node_id;    // 小端
    uint16_t seq;
    uint16_t payload_len;    // 小端
};

// DATA 帧 payload 解析结果
// payload 格式: modbus_type(1) + modbus_len(1) + modbus_rtu(N)
struct SleDataPayload {
    uint8_t  modbus_type;    // 2=电表, 3=温湿度, 4=继电器
    uint8_t  modbus_len;
    const uint8_t *modbus_rtu;  // 指向帧内数据，不拥有内存
};

// TOPO_SUMMARY 帧 payload 解析结果
struct SleTopoHeader {
    uint16_t node_id;
    uint8_t  child_count;
};

struct SleTopoChild {
    uint16_t node_id;
    uint8_t  role;
};
```

## 二、上行数据包格式

### 2.1 HEARTBEAT 帧载荷 (上行)

**载荷格式** (1 字节)：

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | role | SLE 角色 (1=Root, 2=Relay, 3=Leaf) |

**转换为遥测数据后**：
- role 映射为云端角色：Root(1)→0, Relay(2)/Leaf(3)→1
- 加上 DTU 设备名 (如 "DTU_001")
- online = true
- topology: { parent_id, child_count, child_ids }

### 2.2 DATA 帧载荷 (上行 - 电表 modbus_type=2)

**载荷格式**：

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | modbus_type | 0x02 = 电表 |
| [1] | 1B | modbus_len | Modbus RTU 数据长度 |
| [2-N] | NB | modbus_rtu | Modbus RTU 响应帧 |

**Modbus RTU 响应 (功能码 0x04, 16 字节数据)**：

| 偏移 | 寄存器 | 缩放因子 | 单位 | 字段 |
|------|--------|---------|------|------|
| 0-1 | V | ×0.1 | V | voltage |
| 2-3 | I | ×0.01 | A | current |
| 4-5 | P | ×1 | W | active_power |
| 6-7 | PF | ×0.001 | - | power_factor |
| 8-9 | F | ×0.01 | Hz | frequency |
| 10-13 | E | ×0.01 | kWh | energy (uint32) |
| 14-15 | relay | 0x55=ON | - | relay_status |

**Modbus RTU 帧格式**：

```
[slave_addr] [0x04] [byte_count=0x10] [data: 16 bytes] [CRC16: 2 bytes LE]
```

### 2.3 DATA 帧载荷 (上行 - 温湿度 modbus_type=3)

**Modbus RTU 响应 (功能码 0x03, 4 字节数据)**：

| 偏移 | 寄存器 | 缩放因子 | 单位 | 字段 |
|------|--------|---------|------|------|
| 0-1 | RH | ×0.1 | %RH | humidity |
| 2-3 | T | ×0.1 | °C | temperature (有符号) |

**Modbus RTU 帧格式**：

```
[slave_addr] [0x03] [byte_count=0x04] [data: 4 bytes] [CRC16: 2 bytes LE]
```

### 2.4 DATA 帧载荷 (上行 - 继电器 modbus_type=4)

**Modbus RTU 响应 (功能码 0x01, N 字节数据)**：

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0 | coil_byte | bit 0 = relay_state |

**Modbus RTU 帧格式**：

```
[slave_addr] [0x01] [byte_count] [data: N bytes] [CRC16: 2 bytes LE]
```

### 2.5 TOPO_SUMMARY 帧载荷 (上行)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0-1] | 2B | node_id | 上报节点 ID (小端) |
| [2] | 1B | child_count | 子节点数量 |
| [3-5] x N | 3B x N | children | 每个: node_id(2B LE) + role(1B) |

### 2.6 DATA 帧完整示例 (电表)

**SLE 帧头 (13 字节)**：

```
53 54 01 02 01 01 00 02 00 01 00 14 00
│  │  │  │  │  └──┴─┘ └──┴─┘ └──┴─┘ └──┴─┘
│  │  │  │  │    src    dst   seq   len
│  │  │  │  src_role=RELAY
│  │  │  frame_type=DATA
│  │  version=0x01
│  magic_1='T'
magic_0='S'
```

**载荷 (20 字节)**：

```
02 12 [slave_addr] 04 10 [V_hi V_lo] [I_hi I_lo] [P_hi P_lo] [PF_hi PF_lo] [F_hi F_lo] [E_hh E_hl E_lh E_ll] [relay_hi relay_lo] [CRC_lo CRC_hi]
│  │
│  modbus_len=0x12 (18 bytes)
modbus_type=0x02 (电表)
```

## 三、下行数据包格式

### 3.1 继电器控制 Modbus RTU (功能码 0x05)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | slave_addr | 从站地址 |
| [1] | 1B | func_code | 0x05 |
| [2-3] | 2B | coil_addr | 0x0000 + 通道号 |
| [4-5] | 2B | value | 0xFF00=ON, 0x0000=OFF |
| [6-7] | 2B | CRC16 | Modbus CRC |

**完整帧**：`[addr] [05] [00] [channel] [FF/00] [00] [CRC_lo] [CRC_hi]`

### 3.2 电表继电器控制 Modbus RTU (功能码 0x10)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | slave_addr | 从站地址 |
| [1] | 1B | func_code | 0x10 |
| [2-3] | 2B | start_addr | 0x0010 |
| [4-5] | 2B | quantity | 0x0001 |
| [6] | 1B | byte_count | 0x02 |
| [7-8] | 2B | value | 0x5555=ON, 0xAAAA=OFF |
| [9-10] | 2B | CRC16 | Modbus CRC |

**完整帧**：`[addr] [10] [00] [10] [00] [01] [02] [55/AA] [55/AA] [CRC_lo] [CRC_hi]`

### 3.3 完整下行 ST 帧

下行 Modbus RTU 封装在标准 ST 帧中：

```
[13B] ST Header: magic=0x53,0x54, version=0x01, type=DATA, src_role=GATEWAY,
      src_node_id=0x0000, dst_node_id=root_node_id, seq, payload_len
[NB]  Payload: modbus_type(1B) + modbus_len(1B) + modbus_rtu(NB)
```

**关键**：下行 ST 帧的 dst_node_id 固定指向 Root 节点，Root 内部树状转发由 sle_data_app 处理。

### 3.4 下行帧完整示例 (继电器控制)

**Modbus RTU (8 字节)**：

```
01 05 00 00 FF 00 [CRC_lo] [CRC_hi]
│  │  └──┴─┘ └──┴─┘
│  func    coil   value=ON
addr      addr
```

**ST 帧头 (13 字节)**：

```
53 54 01 02 04 00 00 01 00 01 00 0D 00
│  │  │  │  │  └──┴─┘ └──┴─┘ └──┴─┘ └──┴─┘
│  │  │  │  │    src    dst   seq   len=13
│  │  │  │  src_role=GATEWAY
│  │  │  frame_type=DATA
│  │  version=0x01
│  magic_1='T'
magic_0='S'
```

**载荷 (13 字节，最小长度填充)**：

```
04 08 [01 05 00 00 FF 00 CRC_lo CRC_hi] [00 00 00 00 00]
│  │  └──────────────────────────────┘  └─────────────┘
│  modbus_len=8                      padding to 13 bytes
modbus_type=0x04 (继电器)
```

## 四、IPC 命令协议 (Unix Socket)

**定义文件**：`sle_data_app/inc/ipc_cmd_protocol.h`

### 4.1 传输格式

两个通道均使用 2 字节 LE 长度前缀 + 帧体：

```
[2 bytes LE] payload_length
[N bytes]    payload (原始帧数据)
```

| 通道 | Socket 路径 | 方向 | 用途 |
|------|------------|------|------|
| 数据 | `\0/var/run/gateway/sle_data.sock` | sle_data_app → gatewayd | SLE 遥测帧 |
| 命令 | `\0/var/run/gateway/sle_cmd.sock` | gatewayd → sle_data_app | 控制命令 + 响应 |

**注意**：Socket 使用抽象命名空间 (`\0` 前缀)，不是文件系统路径。

### 4.2 命令请求帧 (gatewayd → sle_data_app)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | frame_type | 0x01 = CMD_REQUEST |
| [1-2] | 2B | seq | 序列号 (小端) |
| [3] | 1B | dtu_id | 目标 DTU ID (1-255) |
| [4] | 1B | method | CMD_METHOD_* |
| [5-6] | 2B | param_len | 参数长度 (小端) |
| [7-N] | NB | param_data | JSON 或原始字节 |

**方法 ID**：

| 值 | 名称 | 说明 |
|----|------|------|
| 1 | SET_RELAY | 继电器控制 |
| 2 | SET_MODE | 控制模式 |
| 3 | SET_COLLECT_CYCLE | 采集周期 |
| 4 | TRIGGER_COLLECT | 触发采集 |
| 5 | REBOOT | 重启 DTU |
| 100 | RAW_ST_DOWNLINK | 已封装的 ST 下行帧 |

### 4.3 RAW_ST_DOWNLINK 参数格式

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0-1] | 2B | root_id | 目标 Root 节点 ID (小端) |
| [2-3] | 2B | dst_node_id | ST 帧目标 (小端) |
| [4-5] | 2B | st_frame_len | ST 帧长度 (小端) |
| [6-N] | NB | st_frame | 完整 ST DATA 帧 (最大 256B) |

### 4.4 命令响应帧 (sle_data_app → gatewayd)

| 偏移 | 大小 | 字段 | 说明 |
|------|------|------|------|
| [0] | 1B | frame_type | 0x02 = CMD_RESPONSE |
| [1-2] | 2B | seq | 匹配请求序列号 (小端) |
| [3] | 1B | result_code | 0=OK, 1=FAILED, 2=TIMEOUT, 3=UNSUPPORTED |
| [4-5] | 2B | data_len | 响应数据长度 (小端) |
| [6-N] | NB | data | 响应数据 (JSON) |

**响应码**：

| 值 | 名称 |
|----|------|
| 0 | OK |
| 1 | FAILED |
| 2 | TIMEOUT |
| 3 | UNSUPPORTED |

### 4.5 IPC 帧完整示例 (命令请求)

**数据通道遥测帧 (2B length + ST frame)**：

```
[14 00] [53 54 01 02 01 01 00 02 00 01 00 14 00 02 12 ...]
│  └─┘ └──────────────────────────────────────────────────┘
len=20  ST frame (13 header + 7+ payload)
```

**命令通道请求帧 (2B length + cmd_request)**：

```
[0D 00] [01 01 00 0A 64 12 00 06 01 00 01 00 0D 00 ...]
│  └─┘ │  └─┴─┘ │  │  └─┴─┘ └─┴─┘
len=13  type seq dtu method  param_len
```

## 五、MQTT Topic 结构 (ThingsKit)

**定义文件**：`gatewayd/include/codec/thingskit_topics.h`

| 常量 | Topic | 方向 | 用途 |
|------|-------|------|------|
| kGatewaySubDeviceTelemetryTopic | `v1/gateway/telemetry` | 上行 | 子设备批量遥测 |
| kGatewayTelemetryTopic | `v1/devices/me/telemetry` | 上行 | 网关自身遥测 |
| kGatewayAttributesTopic | `v1/devices/me/attributes` | 上行 | 网关属性 |
| kGatewayCommandRequestTopic | `v1/gateway/commands/request` | 下行 | 网关命令请求 |
| kGatewayCommandResponseTopic | `v1/gateway/commands/response` | 上行 | 网关命令响应 |
| kRpcRequestTopicPrefix | `v1/devices/me/rpc/request/` | 下行 | 单设备 RPC 前缀 |
| kRpcRequestTopicFilter | `v1/devices/me/rpc/request/+` | 下行 | 订阅过滤器 |
| kRpcResponseTopicPrefix | `v1/devices/me/rpc/response/` | 上行 | 单设备 RPC 响应前缀 |

**Topic 前缀配置**：`gateway_config.json` 中 `"topic_prefix": "v1/devices/me"`

**Topic 构建规则** (`mqtt_cloud_client.cpp:205-217`)：
- 如果前缀是 `v1/gateway` 或 `v1/devices/me`：`prefix + "/" + suffix`
- 否则：`prefix + "/" + client_id + "/" + suffix`

**连接后自动订阅**：
1. `v1/devices/me/rpc/request/+` — 单设备 RPC
2. `v1/gateway/commands/request` — 网关命令请求

    "values": {
      "dtu_id": 8,
      "online": 1,
      "temperature": 28.0,

**字段说明**：

**字段说明**：
- `cloud_connected`：1=已连接, 0=未连接 (ENUM 类型)

### 6.3 事件上报 (上行, `v1/devices/me/events`)

- 温湿度：`high_temperature`, `high_humidity` (ALERT 类型)
- DTU：`node_offline` (ALERT), `topology_changed` (INFO)

### 6.5 命令请求 (下行, 云端 → 网关)

**标准格式**：

```json
{
  "requestId": "abc123",
  "device": "RELAY_001",
  "method": "set_relay",
  "params": {
    "state": 1,
    "relay_channel": 0
  }
}
```

**简写格式** (自动转换为标准格式)：

| 简写 JSON | 解析为 method | 解析为 params |
|-----------|--------------|--------------|
| `{"relay_state":1,"device":"RELAY_001"}` | set_relay | `{"state":1}` |
| `{"relay_status":1,"device":"RELAY_001"}` | set_relay | `{"state":1}` |
| `{"control_mode":0,"device":"RELAY_001"}` | set_mode | `{"mode":0}` |
| `{"collect_cycle":5000,...}` | set_collect_cycle | `{"cycle_ms":5000}` |

**目标设备字段提取顺序** (优先级从高到低)：
1. 顶层：`device` → `deviceId` → `deviceName` → `target` → `targetDevice` → `targetDeviceId`
2. params 内：同上字段名

### 6.6 支持的命令方法

| 方法 | 目标设备类型 | IPC 行为 | 状态 |
|------|------------|---------|------|
| set_relay | Relay, SinglePhaseMeter | RAW_ST_DOWNLINK (真实 ST 帧) | 已实现 |
| set_mode | Any | Simulated (占位) | 占位 |
| set_collect_cycle | Any | Simulated (占位) | 占位 |
| trigger_collect | Any | Simulated (占位) | 占位 |
| reboot | Gateway | Simulated (占位) | 占位 |
| ota_upgrade | Gateway | Unsupported (预留) | 未启用 |
| clear_energy | SinglePhaseMeter | Unsupported (预留) | 未启用 |

## 七、物模型定义

### 7.1 网关 (gateway_model.json)

**属性**：
| 属性 | 类型 | 说明 |
|------|------|------|
| network_type | TEXT | 网络类型 (wifi/ethernet/cellular) |
| network_ifname | TEXT | 网络接口名 |
| cloud_connected | ENUM | 0=断开, 1=连接 |
| device_count | INT | 在线设备数 |
| cache_count | INT | 缓存条目数 |
| gateway_version | TEXT | 网关版本 |

**服务**：
| 服务 | 类型 | 输入 | 说明 |
|------|------|------|------|
| reboot | ASYNC | 无 | 重启网关 |
| ota_upgrade | ASYNC | url TEXT, version TEXT | OTA 升级 (预留) |

### 7.2 单相电表 (single_phase_meter_model.json)

**属性**：
| 属性 | 类型 | 说明 |
|------|------|------|
| dtu_id | INT | DTU 节点 ID |
| voltage | DOUBLE | 电压 (V) |
| current | DOUBLE | 电流 (A) |
| active_power | DOUBLE | 有功功率 (W) |
| power_factor | DOUBLE | 功率因数 |
